# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Dev Commands

Package manager: Yarn 4 through Corepack (`corepack enable`, then `yarn install`). The `packageManager` field in
`package.json` pins the version. `npm run <script>` works too for the scripts below; do not use `npm install`.

- `yarn run build` — Compile TypeScript (`tsc`) to `dist/`
- `yarn run dev` — Run server in dev mode via `tsx` (no build needed)
- `yarn start` — Run compiled server from `dist/index.js`
- `yarn run generate` — Regenerate `generated/docs-manifest.json` and `generated/method-registry.ts` from Kotlin KDoc + TS type declarations
- `yarn test` — Run the vitest suite (`test/`), in-memory MCP client against the real server, no network
- `npm run prepublishOnly` — Generate + build (runs before `npm publish`)

The `generate` step requires the parent `cardinal-sdk` repo and `@icure/cardinal-sdk` installed in `node_modules`. It reads Kotlin source files from `../cardinal-sdk/src/commonMain/` and TypeScript declarations from `node_modules/@icure/cardinal-sdk/`.

## Architecture

This is an MCP (Model Context Protocol) server that exposes Cardinal SDK documentation and operational tools over stdio transport. It allows AI assistants to search Cardinal SDK docs and execute SDK operations.

### Entry Flow
- `src/index.ts` — CLI entry point, creates server and connects stdio transport
- `src/server.ts` — Creates `McpServer`, registers all tools and resources

### Tools (SDK Operations)
Tools require SDK initialization via `cardinal_init` before use. All operational tools delegate to `src/tools/dispatch.ts`.

- **`cardinal_init`** (`src/tools/init.ts`) — Initializes `CardinalSdk` with credentials, stores instance in `sdk-state.ts` singleton
- **`cardinal_admin`** (`src/tools/admin-tools.ts`) — Group, User, Role, Permission, System, Auth APIs
- **`cardinal_data_owner`** (`src/tools/data-owner-tools.ts`) — HealthcareParty, Patient, Device APIs with flavour support (decrypted/encrypted/tryAndRecover)
- **`cardinal_crypto`** (`src/tools/crypto-tools.ts`) — Crypto, Recovery, ShamirKeysManager, DataOwner, CardinalMaintenanceTask APIs
- **`search_documentation`** (`src/resources/search.ts`) — Full-text search across docs manifest (no SDK init required)

### Dispatch System (`src/tools/dispatch.ts`)
Generic method dispatch: resolves API object from SDK instance, looks up method in the generated registry (`generated/method-registry.ts`), builds arguments (including filter and model construction), calls method, and serializes the result. Handles `PaginatedListIterator` results via `src/helpers/pagination.ts`.

### Resources (Documentation)
MCP resources serve Cardinal SDK documentation from `generated/docs-manifest.json`:
- `src/resources/overview.ts` — SDK overview
- `src/resources/api-docs.ts` — API method documentation (`cardinal://docs/api/{name}`)
- `src/resources/model-docs.ts` — Model/entity documentation (`cardinal://docs/model/{name}`)
- `src/resources/filter-docs.ts` — Filter documentation (`cardinal://docs/filter/{name}`)
- `src/resources/tutorial-docs.ts` — Tutorial content (`cardinal://docs/tutorial/{slug}`)

### Generated Files (`generated/`)
Do not manually edit. Regenerate with `yarn run generate`.
- `docs-manifest.json` — All documentation data (APIs, models, filters, tutorials) extracted by `scripts/extract-docs.ts`
- `method-registry.ts` — API method signatures and metadata for runtime dispatch, generated by `scripts/generate-registry.ts`

### Helpers (`src/helpers/`)
- `docs-loader.ts` — Loads and caches `docs-manifest.json`
- `filter-builder.ts` — Constructs Cardinal SDK filter objects from plain JSON
- `model-builder.ts` — Constructs Cardinal SDK model instances from plain JSON
- `pagination.ts` — Collects first page from `PaginatedListIterator`, stores iterator for continuation
- `serialization.ts` — Formats SDK results as JSON text for MCP responses

## Automation

- `.github/workflows/update_mcp_server.yml` — when the release PR from `develop` to `main` opens (and on later pushes
  to `develop` touching `ts-wrapper/src/jsMain/**` while it is open), builds the unreleased TypeScript SDK, installs it
  over `node_modules/@icure/cardinal-sdk`, bumps `package.json` to the SDK version, runs generate/build/test, and lets
  Claude reconcile the rest through `.claude/skills/mcp-sync/SKILL.md`. Opens a PR to `develop` on branch
  `mcp-server/sync-<version>`.
- `.github/workflows/publish_mcp_server.yml` — on push to `main` touching this folder, waits for the matching
  `@icure/cardinal-sdk` on npm, then publishes this package with npm trusted publishing (OIDC).
- `SDK.md` is a snapshot of the `sdk/` pages of `icure/medtech-docs` (June 2026), split by `<!-- Source: sdk/... -->`
  markers, plus sections the sync agent adds or extends to document features released since. Those additions live
  only here; the PR body of each sync lists them so they can be ported to `medtech-docs`.
- The package version mirrors the SDK version. `yarn.lock` lags `package.json` by one SDK version between a sync
  and the next; `.github/scripts/mcp-check-yarn-lock-drift.sh` enforces that this is the only drift.
